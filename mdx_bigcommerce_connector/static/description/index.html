Built against the real API, not the docs

Run your BigCommerce store from inside Odoo

Catalog, customers, orders, refunds and abandoned carts — flowing both ways, automatically. Every endpoint in this module was verified against a live BigCommerce store, including the capabilities most connectors quietly skip: multi-storefront channels, price lists bound to customer groups, and abandoned-cart recovery that lands straight in Odoo CRM.

Capabilities

Everything in one module

No paid add-ons, no per-feature upsells.

Full catalog

Products, every variant, modifiers, categories and brands. Product images are downloaded and stored in Odoo, not just linked — so they survive BigCommerce rotating its CDN URLs.

Multi-storefront

BigCommerce channels mirror into Odoo as storefronts, each mappable to its own pricelist. Revenue splits per storefront on the dashboard.

Carts → CRM leads unique

Abandoned carts arrive in real time and convert to a CRM lead in one click — customer, contents and value pre-filled. No competing connector offers this.

Orders & refunds

Orders import at the exact totals BigCommerce charged, on a workflow you choose — quotation, confirmed, invoiced, or invoiced and paid. Refunds can raise a credit note automatically.

Webhooks + schedule

Real-time events for orders, products, inventory, carts and refunds, with cron catch-up behind them. Webhooks BigCommerce auto-disables are flagged, not lost silently.

Two live dashboards

Sales — revenue windows, per-storefront split, cart-recovery rate. Catalog — sync health, stock health, top brands and categories.

Installation

Connected in about ten minutes

Follow the order — later steps depend on earlier ones.

1

Create BigCommerce API credentials

In BigCommerce go to Settings → API → Store-level API accounts → Create API account. No App Marketplace listing or OAuth callback needed. Grant these scopes:

Scope Level Needed for
Products Modify Catalog sync, price/stock push, publishing
Orders Modify Order import and status updates
Customers Modify Customers and customer groups
Carts Read-only Abandoned-cart capture
Information & settings Read-only Connection test, storefront list

Copy the Client ID, Access Token, and your store hash — the code in the API path: api.bigcommerce.com/stores/xxxxxxxx/v3/

The access token is displayed once. Copy it before closing the dialog.
2

Install the module

Place it in your addons path, then Apps → Update Apps List, search BigCommerce Connector, and Install. A BigCommerce menu appears in the app switcher.

3

Connect the store

BigCommerce → Configuration → Stores → New. Enter the three credentials, then set your warehouse, default pricelist and currency.

Pick an Auto Order Workflow: create a quotation, confirm the sale order, also invoice it, or invoice and register payment. Start on Create Quotation until you trust the data.

Press Test Connection — the status turns Connected and shows your store domain.

4

Run the first sync

Press Sync All Now. It runs in dependency order:

Storefronts → Categories → Customer Groups → Price Lists → Customers → Products → Orders

Products need categories first; orders need products and customers. Watch Configuration → Sync Log — a product that fails is flagged on its own rather than killing the whole batch.

5

Enable real-time webhooks

Press Register Webhooks to subscribe BigCommerce to push order, product, inventory, cart and refund events as they happen.

Your Odoo must be reachable from the internet — BigCommerce cannot call localhost. Set Settings → Technical → System Parameters → web.base.url to your public URL first. On a local install, skip this and rely on the scheduled sync.
6

Map storefronts and customer groups

Under Configuration → Storefronts give each BigCommerce channel an Odoo pricelist, and do the same per group under Catalog → Customer Groups. Imported orders and customers then land on the correct pricelist automatically.

7

Review the scheduled jobs

Two crons install enabled — orders every 15 minutes, products and inventory every 30. Tune them in Settings → Technical → Scheduled Actions (search "BigCommerce"). They are the safety net behind the webhooks.

Day to day

The things you'll actually do

Import one specific BigCommerce record
Configuration → Targeted Import. Choose the entity — products, orders, customers, categories or price lists — then Specific BigCommerce IDs and type them, e.g. 77, 80, 88. An ID range or a full import are also available. Ideal for pulling in one new product without re-syncing the whole catalog.
Publish an Odoo product to BigCommerce
Create the product in Odoo, then select it and use Actions → Publish to BigCommerce. Pick the storefront category and whether to push current stock. It is created on BigCommerce and linked back, so later price and stock pushes know where it lives. Products already linked are skipped — safe to re-run.
Bulk update from a spreadsheet
Catalog → Bulk Update. Choose the operation, switch Source to Upload a file, grab the sample, fill it in and upload. One file can set a different price, stock level, MOQ or tax code for every SKU. Prefer clicking? Tick rows in Products or Variants and use Actions → Push to BigCommerce instead.
Recover an abandoned cart
BigCommerce → Carts opens filtered to abandoned carts. Open one and press Convert to CRM Lead — you get a lead carrying the customer, the cart contents and the cart value as expected revenue, ready to assign.
Full disclosure

What this module does not do

Stated up front, so nothing surprises you after purchase.

  • Carts cannot be bulk-imported. BigCommerce exposes no endpoint that lists carts, so they are captured live through webhooks only. Historical carts cannot be backfilled — by this or any other connector.
  • Per-line tax is not mapped to Odoo tax records. Orders import at the exact totals BigCommerce charged, with Odoo taxes cleared, so figures always match the storefront. Mapping BigCommerce tax lines onto Odoo tax codes is not included.
  • Refunds are one-way. Refunds made on BigCommerce flow into Odoo and can raise a credit note. Issuing a refund from Odoo back to the BigCommerce payment provider is not supported.
  • One stock location per store. BigCommerce tracks a single quantity per variant, so stock syncs against one nominated Odoo warehouse. Multi-location allocation stays in Odoo.
  • Webhooks need a public URL. On a laptop or private network real-time events will not arrive; the scheduled sync covers you.
Support

Troubleshooting

Symptom Fix
401 Unauthorized on Test Connection Store hash, client ID or access token is wrong. Regenerate the API account and re-enter all three.
404 Not found on Test Connection Almost always the store hash — copy only the code from the API path, not the whole URL.
Orders import with no lines Sync products first. Order lines only link to variants that already exist in Odoo.
A webhook stopped firing BigCommerce disables a webhook after repeated delivery failures. Auto-disabled hooks are flagged red under Configuration → Webhooks. Restore reachability, then Register Webhooks again.
A product shows a red error state Open it — the reason is on the form and the full message is in the Sync Log. Fix it, then press Sync Now on that product alone.
Uploaded file rejected It needs a sku column and must keep its .csv/.xlsx/.ods extension. The error names the columns it actually found.
